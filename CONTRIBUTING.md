# Contributing to CORE

Start with the README and `content/guidance/production.md`. Open an issue for
uncertain teachings, substantial additions, translation plans or accessibility
problems. A useful report identifies the page, the problem, the proposed
correction and any primary source or reproduction steps.

1. Create a branch and edit the appropriate Markdown source. Do not edit `dist/`.
2. Keep the JSON front matter valid and preserve published session slugs.
3. Use primary Catholic sources with exact paragraph or section references.
   Distinguish doctrine, discipline, historical interpretation and optional devotion.
4. Check quotation wording and context. Record edition, translator, locator,
   URL and rights status. Add no invented sayings or unlicensed images.
5. Retain the welcome, participation choices and pastoral boundaries. Never use
   real participants' sensitive stories as examples without appropriate permission.
6. Run `npm run check`. Inspect changed session pages on narrow and wide screens;
   check keyboard navigation, reduced motion, dark theme and the generated PDF.
7. Explain what changed and how it was checked in the pull request.

Contributors must have the right to submit their work. Original code contributions
use MIT; original course content uses CC BY-SA 4.0. Clearly identify third-party
material and its separate terms. Contribution does not confer authority to make
doctrinal claims or claim ecclesiastical approval. Qualified human theological
review and the applicable ecclesial process remain separate release gates.

Keep source and learner outcomes aligned. If a session needs more time, use the
documented pacing options instead of removing essential teachings. Core teaching,
answers, source references and accessibility alternatives must remain free.
